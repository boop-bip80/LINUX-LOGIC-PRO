## Exact implementation and acquisition assessment

The audit compares the reviewed workflow and seven production Python files
byte-for-byte with `git show d58cca51:<path>` and records their SHA-256 values.

source. Review covered the following relationships, with independent negative
fixtures for the consequential integrity claims below:

- The workflow supplies the immutable GitHub revision and separate runner
  destinations. Checkout does not persist credentials. The ordinary campaign
  starts with an absent destination and uses public HTTPS `git clone
  --no-local --no-hardlinks --no-checkout --no-recurse-submodules`, detached
  exact-SHA checkout, and ordinary `git submodule update --init --recursive`.
  The recorded source and acquisition paths are distinct. The command lists
  contain no reference store, alternate, shared clone, bundle, or mirror.
- The campaign strips ambient Git selectors and token/password/secret
  variables, disables credential helpers and HTTP extra headers, ignores
  global/system Git config, refuses netrc-based acquisition, and disables
  hooks and fsmonitor. These are properties of the source actually used by
  the captured commands; the summary's anonymous-acquisition flag is not the
  sole basis for this conclusion.
- Every visited repository must reject nonempty local attributes and object
  alternates. Each child must be a real, confined checkout with the locked
  origin, HEAD and tree. Complete tree/index equality and recursive ownership
  precede a successful result. The independent existing-destination fixture
  proves the acquisition entry point refuses reuse before issuing a command.
- Physical verification hashes actual regular bytes and symlink text against
  canonical Git blob identities and checks executable mode. Directory/leaf
  access uses no-follow descriptors. Index assume-unchanged state does not
  waive those checks. CRLF reads now recompute the canonical object digest,
  closing the corrupt-loose-blob false pass documented by the repair author.
- Regeneration runs `make_submodule_lock.py --evidence-mode reviewed-current`
  from the acquired clone and requires byte equality. This review checks the
